# note の収益化モデルの比較と、AI による自動化の検討

動画の分析(research/youtube/)と note の公式情報(note_platform_2026.md)をもとにした、分析者(Claude)の整理です。
動画の内容そのものは各分析ノートを参照してください。ここでは「どの動画の主張か」を【】で示します。

## 1. 手数料と「手元に残る額」(note 公式の料率で計算)

計算式:手元に残る額 = 価格 ×(1 − 事務手数料)×(1 − プラットフォーム利用料)。振込のたびに別途270円。

| 価格 | クレジットカード(5%) | PayPay(7%) | 携帯キャリア(15%) |
|---|---|---|---|
| 300円 | 256円 | 251円 | 230円 |
| 500円 | 428円 | 418円 | 382円 |
| 980円 | 838円 | 820円 | 750円 |
| 1,500円 | 1,282円 | 1,256円 | 1,148円 |
| 2,980円 | 2,548円 | 2,494円 | 2,280円 |

- 有料記事・有料マガジン・メンバーシップは利用料10%で同じ。定期購読マガジンは20%(500円ならカード決済で380円)
- 手元に残るのは、ざっくり価格の8割強(カード決済の場合は約85%)

## 2. 目標に必要な販売数(カード決済で計算、振込手数料270円を月1回として、端数は切り上げ)

| 目標(手取り) | 500円 | 980円 | 1,500円 | 2,980円 |
|---|---|---|---|---|
| 月1万円 | 25件 | 13件 | 9件 | 5件 |
| 月5万円 | 118件 | 60件 | 40件 | 20件 |
| 月10万円 | 235件 | 120件 | 79件 | 40件 |

- メンバーシップ(月額)の場合は「件数」を「会員数」と読みかえる。たとえば月額500円なら、手取り月1万円に25人、月5万円に118人
- 【ひらかわ・ねこ太・かけち】が共通して言う「目標を単価×人数に分解する」を数字にしたもの。単価が低いほど、必要な人数が一気に増える

## 3. 収益化モデルの比較

難易度・収益性は、動画の主張と公式データをもとにした分析者の見立て(5段階、★が多いほど難しい/大きい)。

| モデル | しくみ | メリット | デメリット | 難易度 | 収益性 | 主な根拠 |
|---|---|---|---|---|---|---|
| 有料記事(単発) | 1テーマ1回払いの買い切り。無料部分で引きつけ、有料部分で解決 | 1回作れば売れ続ける。リライトで育てられる。「単価×人数」で計画しやすい | 毎回「買う理由」を作る必要。最初の1人に売るのが一番むずかしい | ★★★ | ★★★〜★★★★★(単価しだい) | ひらかわ、ねこ太、うと、ぽにょ、かけち。公式:実用系の売れ筋平均1,842円 |
| 有料マガジン(まとめ売り) | 有料記事を複数まとめてセット価格で売る | 1人あたりの購入額が上がる。章立ての連載と相性がよい | 単品が売れていないと効果が薄い | ★★ | ★★★ | うと(2本以上ならやった方が得)、かけち(3本まとめで4,480円) |
| メンバーシップ(月額) | 会員に限定記事・掲示板・質問対応などを毎月届ける | 収入が予測しやすい。公式データで伸びている(+81%) | 続ける理由を毎月作る・解約がかんたん・集客し続ける。約束が負担になる | ★★★★(初心者) | ★★★★(常連がいれば) | うと(最初はやらない)、公式データ、料理家の例(月580〜880円) |
| 定期購読マガジン | 月額で、毎月更新するマガジン | 連載と形が合う | noteプレミアムが必要、利用料20%、毎月更新しないと廃刊。メンバーシップの方が条件がよい | ★★★★ | ★★ | 公式ヘルプ、うと(今は使うメリットが少ない) |
| アフィリエイト | 記事で他社の商品(Amazon・楽天など)を紹介し、売れたら報酬 | 自分の商品がなくても始められる。料理なら調理道具・食材と相性がよい | 報酬率が低く、件数が必要。PR 表記が必要(ステマ規制)。Amazon は2026年4月に規約改定。楽天は note で使えるが、サイト登録・自己購入の禁止・レビュー転載の禁止・画像の加工の禁止・他人のコメント欄への掲載の禁止などの決まりがある(公式で確認) | ★★★ | ★〜★★ | 公式・報道、ゆか(手順と規約。収益の数字はなし)。ルパン15世の「他サイトの情報商材のアフィリエイト」は note の外の話で、料理には合わない |
| SNS からの集客 | X・Threads などで悩みに刺さる投稿 → プロフィール → 記事 | 需要を書く前に確かめられる。最初の売上が早い | 毎日の投稿の負担。インプレッションと売上は比例しない。アカウント停止の危険 | ★★★ | 集客手段(単体では稼がない) | ねこ太、かけち、らっこ、シズマ(失敗) |
| 無料記事 → 有料記事の誘導 | 潜在層向けの無料記事から、顕在層向けの有料記事へリンク | SNS なしでも note の中で回る。記事が資産としてたまる | 無料記事の数が必要。SNS なしでは月2〜3万円が上限という見立て | ★★ | ★★〜★★★ | ぽにょ、在宅ワーク講座、ひらかわ(無料部分) |
| 複数の記事を組み合わせた販売 | 入口の安い記事 → 本命 → まとめ/関連の悩みごとに1本ずつ → 上位の商品 | 1人あたりの購入額が上がる。読者の段階に合わせられる | 設計が必要。煽り売りにならない注意 | ★★★ | ★★★★ | かけち、ねこ太(関連の悩みごとに1本)、らっこ(アップセル) |
| チップ | 応援の気持ちで読者が払う | 思わぬ収入になる | 目的にするのはむずかしい | ★ | ★ | うと |
| 記事をきっかけにした別の売上(副産物) | 有料記事を読んで行動した人が必要になるもの(ツール・業者など)の紹介料 | 読者の成功と自分の売上が一致し、継続的に入る | ジャンルしだいで作れない。料理では本人が使う道具の紹介くらい | ★★★ | ★★〜★★★★(ジャンルによる) | ひらかわ |
| 無料記事で名簿を集め、note の外の講座で収益化 | 無料記事 → LINE → 無料ウェビナー → 個別相談 → 高額の講座 | 有料記事を作らなくてよい | note の外に自分の商品が必要。強引な勧誘に見えやすい | ★★★★ | ★★★★(講座がある人) | いむ先生 |

### 比較から言えること

- 最初の柱は「有料記事(単発)」。どの投稿者も一致して推し、計算もしやすい
- 有料記事が2本以上になったら「有料マガジン」でまとめる
- メンバーシップは、常連さん(購入者)ができてから。料理の分野では先行例があり、月500〜900円台が相場
- 集客は「無料記事 → 有料記事」を土台にし、SNS は需要を確かめる場として使う
- アフィリエイトは料理と相性がよいが、収益の柱ではなく補助と考える。紹介するのは本人が実際に使っている道具(はかり・温度計など)だけにし、記事の理屈とつなげて、よい点と合わない点の両方を書く【ゆか】。どれくらい稼げるかを示した動画はなく、計画の数字には入れない

## 4. AI による自動化の検討(Claude 中心)

前提:動画で一致しているのは「AI は手足、判断は人」【ぽにょ・らっこ・かけち・うと・ニートパパ・SHIFT AI・ひらかわ】。AI から出てくるものの質は「渡す材料」(本人の経験)で決まる【ひらかわ】。AI に丸投げした記事は売れない、という指摘も多い【ぽにょ・うと】。
このリポジトリでは、すでに「Claude が下書き → tools/check.py で機械チェック → 本人が添削」の流れがある。これを広げる形で考える。
※AI 活用を扱う動画4本(Claude での有料記事作成の実演【ニートパパ】、Claude Code × note の自動化【SHIFT AI】、AI×note の弊害【ひらかわ】、AI 丸投げの実演【うと】)をすべて反映済み。

| 作業 | Claude にやらせること | 併用する道具 | 人が残す判断 | 根拠となる動画 |
|---|---|---|---|---|
| 市場・需要のリサーチ | note の料理の話題・有料記事・メンバーシップの価格を調べてまとめる。X・Threads の反応の多い投稿を集めて、悩みを分類する | Claude のウェブ検索。X の検索(min_faves で絞る)。Claude in Chrome(デスクトップアプリ) | 最初の数回は本人が自分の目で見る。最後の採否 | ねこ太、かけち、ぽにょ、らっこ |
| 売れるテーマの発掘 | 本人が音声入力で話した経験(5つの質問への答え)から、「当時の悩み → 同じ悩みの人 → 欲しい解決策」に整理し、テーマ候補を出す。Claude から本人に質問して(インタビュー)、答えから「一番痛かった場面」「当時の思い込み」を抜き出す | スマホ・PC の音声入力(Typeless など) | 経験の中身は本人のもの。作り話にしない。本当の原因を決めるのは本人 | ひらかわ(AI は聞き手)、ねこ太、SHIFT AI(インタビューで素材を作る)、ニートパパ(足りない情報を質問させる) |
| 本人の考え方の蓄積 | 本人が話した方針・考え方・経験を md ファイル(「脳みそファイル」)にためていき、下書きのたびに読む。ネットの情報や Claude の推測は入れない | md ファイル(リポジトリ内) | 書き足してよいかの確認 | ひらかわ、SHIFT AI(指示書) |
| 競合記事の分析 | 料理の大手アカウント・有料記事の無料部分を読み、「拾えていない悩み」「難しくてついていけない人」を出す | Claude in Chrome、または本人が URL や本文を貼る | どこで差をつけるかの決定 | かけち、ぽにょ |
| 記事構成の作成 | topics.md とテンプレートから構成案を出す。有料記事は「変化の約束 → 共感 → 道のり → 最初の一歩」で、有料部分を先に、無料部分をあとに書く【うと】。中身は7つの切り口(考え方・初心者向け・細かいコツ・数値の基準・時短・やってはいけない例・実例)で点検する。まず構成案だけ、OK なら章ごとに本文 | templates/article.md | 構成の承認 | ひらかわ、かけち、ニートパパ |
| 本文の執筆補助 | CLAUDE.md(指示書)を読んで下書きを書き、確認が必要な所に ==ハイライト==【確認:…】をつける。経験談は場所だけ示す。有料記事は章ごとに区切って書く | tools/check.py | 数値・安全の確認、経験談の記入、最終の文責 | (このリポジトリの仕組み)、SHIFT AI(指示書)、ニートパパ(区切って書く)、うと(丸投げは電子ゴミ) |
| 中身の見直し | check.py(形のチェック)のあとに、「別の編集者の視点」で事実の怪しい所・言いすぎ・読みにくい所を、場所を挙げて指摘する | tools/check.py の結果 | 指摘の採否。数値・固有名詞・安全は本人が一次情報で確かめる | SHIFT AI、ひらかわ(研究や数字は元の出典を確認) |

| 投稿スケジュール管理 | progress.md の投稿予定日を管理し、週ごとに「次に書く・添削する・投稿する」を一覧にする | Claude Code の定期実行(ルーティン)、Google カレンダー | 予定の決定 | (このリポジトリの仕組み) |
| アクセス・売上の分析 | 毎週の数字(ビュー・スキ・購入数・売上)を表にためて、「見られていない/買われない/反応が薄い」に分けて原因を出す | note のダッシュボード(API はないので本人が数字を写す)、Google スプレッドシート | 数字の入力、解釈の確認 | ねこ太 |
| 改善案の自動生成 | 分析結果から、直す記事・直す場所(タイトル/無料部分/中身)と案を出す。次に書くテーマの優先順位を出す | 上と同じ | 実行するかの判断 | ねこ太、ひらかわ(リライトで育てる) |

### 自動化しないこと(線引き)

- note への投稿そのもの:note には投稿用の公開 API がない。ブラウザを自動で動かして投稿するのは、規約や安全の面で避け、投稿は本人が行う。Claude in Chrome で note の下書きに入れ、公開だけ人が押すやり方もある【SHIFT AI】が、本人のパソコンでの設定と、note の規約での扱いの確認が必要(未確認)なので、いまは選択肢にとどめる
- 経験談・数値・安全の最終確認:本人が行う(連載の決まり)
- 煽りの強い販売文(6つの教育などを過度に使うこと):使うなら本人が内容を確かめる
